# 健康面板与快速诊断（唯一权威定义）

> 触发词：「skill 健康状态」/「skill 趋势」/「哪些 skill 在下降」/「skill health」。**只读**：不创建分支，不修改任何文件。

## 快速诊断入口工作流

1. 读 `results.tsv`（不存在 → 提示「暂无历史数据，请先运行评估」，结束）
2. 读 `results.json`，展示 `evaluated_at`
3. 按 skill 分组统计 keep/revert 率
4. 展示下方三部分健康面板
5. 列出保留率 < 60% 的 skill，提示：`输入「优化 {skill名}」开始改进`
6. **只读，不创建分支，不修改任何文件**

> 若 `results.tsv` 不存在，跳过整个面板并输出：`（暂无历史数据，健康面板不可用）`

## 面板格式

### 成功率趋势

按 skill 分组，统计 `status=keep` 占 `keep+revert` 总轮次的百分比，附趋势符号（↑=本次>上次 / ↓=下降 / →=持平）。

```
## 健康面板（基于 results.tsv，最近评估：{evaluated_at}）

### 成功率趋势
| Skill          | Keep 率 | 趋势 | 备注 |
|----------------|---------|------|------|
| code-review | 90%    | ↑    |      |
| sql-gen     | 50%    | ↓    | ⚠️ 近7天保留率<60%，建议重新评估 |
```

⚠️ 标记：保留率 < 60% 的 skill 列入需关注列表，在面板末尾给出建议指令。

### 失败模式聚类

从 `status=revert` 行的 `note` 列提取关键词，按频次排序展示前 3 类：

```
### 失败模式（前3类）
| 模式           | 次数 | 占比 |
|----------------|------|------|
| 指令具体性     | 5    | 42%  |
| 边界条件       | 4    | 33%  |
| Frontmatter    | 3    | 25%  |
```

若无 revert 记录，输出：`（本批次无回滚记录）`。

### 版本历史摘要

每个 skill 展示 baseline → 最新分数变化链（最多近 5 轮）：

```
### 版本历史摘要
- code-review：61.2 → 67.2 → 71.2 → 76.7 → 94.0（+32.8）
- sql-gen：70.0 → 74.0（+4.0）
